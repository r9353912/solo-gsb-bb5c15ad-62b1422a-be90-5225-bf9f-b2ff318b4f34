# 盲文标签排版台（Braille Label Studio）

输入英文标签文字与板材宽/高、点距、行距，系统按**六点一级盲文**转换并排版；也提供反向的**点阵解码**工具（粘贴六点盲文 Unicode 字符串即还原英文、大小写与连续数字段）；支持**多标签拼版**（每行一条标签、0/90° 旋转、行级装箱到整张板材）；单标签或拼版成功后可生成**压印路径**（压印机逐点作业顺序）；另提供**压印质检**模式，将实测凸点 CSV 与最近一次成功排版（单标签或拼版）的设计点逐一比对：

- **点阵解码**：粘贴六点盲文 Unicode 字符串，按排版台**同一套字符表**反向还原英文文本——大写前缀 `⠠`（点 6）还原大小写、数字前缀 `⠼`（点 3-4-5-6）开启连续数字段（a–j 点位还原 1–0，段内小数点/逗号不切段），**空白（含盲文空白单元 `⠀` 与换行）和标点原样保留**；非盲文字符或码表未收录的盲文点位**绝不静默丢弃**——`decodedText` 中原样保留，并在 `errors[]` 中**逐个**给出字符位置、Unicode 码点（如 `U+283F`）与原因；页面支持错误点击定位、逐单元对照与一键复制结果
- 大写字母前自动添加大写前缀 `⠠`（点 6）
- 连续数字段只在段首添加一个数字前缀 `⠼`（点 3-4-5-6）
- **单标签排版**：依据转换后的盲文单元**整词换行**，词间空一个空白单元
- 任何单词放不下、或总行数超出板材容量时，**明确指出原因，绝不裁切**
- **多标签拼版**：多行标签逐条复用同一套盲文转换，每条作为**不可拆分矩形**做带边距的二维行级装箱，允许 **0°/90° 旋转**，按**剩余面积最小 → y → x → 0°** 稳定择优；任一标签放不下时逐条给出原因且不输出部分版面
- **拼版裁切线**：复用一次**成功拼版**的每条标签全局凸点、编号与板材尺寸，输入**凸点到成品边的最小留边**与**刀具半径**——按“凸点中心 + 凸点半径”形成包络，外扩留边生成各标签**矩形成品边**、再外扩刀具半径得到**刀心线**（旋转标签也按全局坐标计算）；系统计算受**板材边缘**与**标签之间刀具占位**共同约束的**整版最大统一留边**，输入留边超限时逐条指出限制它的板边或标签对、**不输出部分刀路**；可行时在拼版预览上**叠加裁切线**并导出含**标签编号与刀心线四角毫米坐标**的 **CSV 与 SVG**
- 页面实时预览带毫米（mm）坐标的凸点 SVG（拼版同时画出**每个标签的边界与索引/旋转角**），并可下载 **SVG** 与**排版 JSON**（含标签索引与旋转角）
- **压印路径**：单标签排版或多标签拼版成功后，指定压印起点 (X/Y mm) 即可生成压印机逐点作业顺序——先以**最近邻**从起点走出初始路线，再执行**最多 20 轮 2-opt**（每轮按反转段起止下标顺序接受首个**严格缩短**的反转）；同距离时按**标签索引 → 点坐标 (x,y) → 原序号**稳定决胜，相同输入结果严格一致，**每个凸点恰好访问一次**。界面显示优化前/后空移总长与节省比例，叠加预览画出带 step 序号与方向箭头的路径，可下载含 `step,label,x_mm,y_mm,travel_mm` 的 CSV；**点数超过 2000 或参数非法时明确报错，不输出部分路径**
- **压印质检**：粘贴实测凸点 CSV、设置校准旋转角/偏移/合格公差/关联半径，叠加 SVG 区分四类结果并下载质检报告 CSV；质检页可一键选择**最近一次成功的单标签排版或多标签拼版**作为基准——拼版基准显示标签数量及各标签索引/旋转角，请求直接使用拼版返回的顶层 `dots`（保留 `label`、`rotation` 元数据），叠加图与 CSV 报告会标注每个结果所属标签；尚无成功拼版时拼版基准按钮禁用并提示先完成拼版
- **自动校准**：实测点顺序无须对应，设置 X/Y 最大校准量后一键估算全局平移并写回偏移、自动重跑；另可设置**最大旋转角与角度步长**启用**小角度刚体校准**（围绕板材中心的旋转 × 平移联合搜索）；正确处理缺失点与多余点，不使用质心差

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

Compose 会在构建镜像时自动完成依赖安装与初始化。启动后**页面与全部 HTTP API 均在 3000 端口**，浏览器访问：

**http://localhost:3000** （容器内外端口均为 `3000`；API 前缀同为 `http://localhost:3000/api/...`）

页面顶部四个页签即为入口：

- **点阵解码**（顶部「点阵解码」页签）：粘贴六点盲文 Unicode 字符串，即时还原英文文本、显示逐单元（cells）对照；未知字符逐个列出位置/码点/原因，点击错误可在输入框定位，「**复制解码结果**」一键复制 `decodedText`；
- **排版模式**（`http://localhost:3000/`，默认页签）：单标签盲文转换、整词换行排版与 SVG/JSON 下载；左侧表单底部「**压印路径**」区域可直接对当前排版凸点生成逐点作业顺序；
- **多标签拼版**：点击顶部「**多标签拼版**」页签，每行输入一条英文标签，整板预览标签边界与凸点，下载含标签索引/旋转角的 SVG/JSON；左侧内置「**压印路径**」与「**拼版裁切线**」两个区域，可分别对整板全部凸点生成路径、对成功拼版生成裁切线；
- **压印质检**：点击顶部「**压印质检**」页签进入，通过左侧「单标签排版基准 / 最近拼版基准」按钮选择当前会话中最近一次成功的单标签排版或多标签拼版作为质检基准。

停止：`docker compose down`

## 点阵解码模式

点击顶部「**点阵解码**」页签，在左侧文本框粘贴**六点盲文 Unicode 字符串**（如排版结果中的盲文对照行，支持多行、≤5000 字符），输入后自动防抖解码（接口 `POST /api/decode`；服务不可用时浏览器端用同一份 `lib/braille.js` 同构回退）。

解码规则是正向转换的严格逆过程，与排版台共用同一张字符表：

| 盲文单元 | 还原结果 |
| --- | --- |
| 字母点位 a–z | 小写字母；紧邻其前的大写前缀 `⠠`（U+2820）使其还原为大写 |
| 数字前缀 `⠼`（U+283C）+ a–j 点位 | 开启**连续数字段**，a–j 依次还原 1–0；段内只在段首消耗一个 `⠼` |
| 数字段内的 `.` / `,` | 视为数字胶着标点（`3.14`、`1,000`），不切断数字段；k–z 字母与其他标点结束数字段 |
| 标点点位 | 按码表还原（`,` `;` `:` `.` `!` `?` `'` `-` `(` `)` `/` `&` `*` `@` `#` `+` `=`） |
| 普通空白 / 换行 / 盲文空白单元 `⠀`（U+2800） | **原样保留**为空白 |

码表存在两处固有的同点位情况，反向解码按以下确定规则处理：

- **数字与 a–j 字母同点位**：一级盲文中数字复用 a–j 点位，且本字符表不使用字母符，故数字段内紧跟的 a–j 一律按数字还原（如 `⠼⠁⠃` 还原 `12`）；要在数字后接 a–j 字母，字母需位于空格/标点/k–z 之后的新段；
- **`⠼` 与标点 `#` 同点位**：仅当处于非数字段且紧邻 a–j 点位时按数字前缀处理，其余（含段内冗余 `⠼`、后接非数字单元）按 `#` 还原；
- `(` 与 `)` 与 `=`、`!` 与 `+` 同点位，反向统一取码表中先定义的符号（分别还原 `(`、`!`）。

**未知字符绝不静默丢弃**：以下情况 `ok=false`，但 `decodedText` 仍把原字符**原样保留**，并在 `errors[]` 中**逐个**给出 `position`（输入字符串中的 UTF-16 字符偏移，可直接用于输入框选区定位）、`codePoint`（如 `U+4E2D`、`U+283F`）、`dots`（若为盲文图案）与中文原因：

- 非盲文图案字符（不在 U+2800–U+28FF 区间，如直接粘贴了 ASCII、汉字）：类型 `unknown-char`；
- 盲文图案但点位未被字符表收录：类型 `unknown-pattern`；
- 悬空的大写前缀 `⠠`（位于结尾或后一个单元不是字母，如 `⠠ `、`⠠⠼`）：类型 `dangling-caps-prefix`。

界面右侧显示只读的**还原文本**、单元/字符计数与**逐单元对照**（每个单元的盲文原字、点号、类型、还原字符；错误单元标红），点击任意错误条目或单元即在左侧输入框选中对应字符；「**复制解码结果**」复制 `decodedText`（含保留的未知字符）。

## 使用说明（排版模式）

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| 标签文字 | 英文标签（A–Z、a–z、0–9 及常用标点，≤500 字符） | `EXIT Door 2` |
| 板材宽度 / 高度 | 标签板材幅面，单位 mm | 100 × 50 |
| 点距 | 单元内相邻凸点中心距，单位 mm | 2.5（标准盲文） |
| 行距 | 相邻两行顶行点的中心距，单位 mm | 10（标准盲文） |
| 边距（高级） | 板材四周边距，单位 mm | 5 |
| 字距（高级） | 相邻单元净间距，留空 = 1.4×点距（标准 → 6mm 单元pitch） | 自动 |
| 凸点直径（高级） | 留空 = 0.6×点距（标准 ≈1.5mm） | 自动 |

放不下时的报错示例：

- `单词 “EXIT” 转换后占 6 个盲文单元（含大写/数字前缀），超过每行最多 4 个单元……`
- `整词换行后共需 5 行，板材有效高度仅容纳 4 行……`

## 多标签拼版模式

在「多标签拼版」页签的文本框中**每行输入一条英文标签**（空行自动跳过并计入“跳过空行”），所有标签共享同一组板材 / 点距 / 行距 / 边距 / 标签间距参数。

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| 多条标签 | 每行一条英文标签（A–Z、a–z、0–9 及常用标点）；单次 ≤100 条、每条 ≤500 字符 | 5 条示例 |
| 板材宽度 / 高度 | 整张拼板幅面，单位 mm | 120 × 80 |
| 点距 / 行距 | 与单标签排版相同：单元内点中心距 / 相邻行中心距 | 2.5 / 10 |
| 板材边距（高级） | 板材四周内边距，所有标签矩形必须落在该有效幅面内 | 5 |
| 标签间距（高级） | 相邻标签矩形之间的水平 / 竖直净间距 | 5 |
| 字距 / 凸点直径（高级） | 同单标签排版，留空自动 | 自动 |

算法说明：

1. **逐条复用单标签盲文转换**：每条标签按单行生成盲文，得到一个**不可拆分矩形**（宽 = 单行单元占宽，高 = 2×点距）；
2. **带边距的二维行级（shelf）装箱**：从上到下开“行”，行内从左到右摆放，标签间留标签间距；
3. 每个标签枚举 **0° 与 90°（顺时针）** 两种朝向，候选位置包括“每个现有行内剩余处”与“新开一行”，按
   **① 放入后已装区域剩余面积最小**（标签面积在旋转下不变，等价于已装包围盒面积最小）→ **② y 最小 → ③ 包围盒左缘 x 最小 → ④ 优先 0° → ⑤ 行序号最小**
   选出唯一位置，结果完全确定、可重复；
4. **任一标签**含不支持字符、**0° 与 90° 都超出板材有效幅面**、或装箱阶段**在任何行（含新开行）都放不下**时，接口返回**逐条**错误（标签序号 + 具体尺寸/幅面原因），并且 `ok=false`、`svg/dots/labels` 全为空——**绝不输出部分版面**。

预览与下载：

- 整板 SVG 画出板材、边距参考线、**每个标签的边界矩形（蓝色 0° / 橙色 90°）、索引与 `⟳90°` 标记、`<title>` 悬停原文**及全部凸点；每组带 `data-label-index` 与 `data-rotation`；
- **下载拼版 JSON**：`labels[]` 逐条给出索引、源行号、原文、盲文 Unicode、旋转角（0/90）、锚点与包围盒 `bounds{x,y,width,height}` 及该标签全局凸点；顶层 `dots[]` 为全部凸点展平（含 `label` 与 `rotation` 字段），**字段结构是单标签 `dots{x,y,r}` 的超集，可直接作为 `/api/qc` 的设计点基准**；
- 统计含标签数、旋转数、已装区域 `packWidth × packHeight`、标签总面积与**剩余面积**。

放不下时的报错示例：

- `标签 #3「…」单行盲文尺寸为 176.5 × 5 mm（宽 × 高），即使旋转 90°（5 × 176.5 mm）也超出板材有效幅面 110 × 70 mm……`
- `标签 #4「…」（尺寸 86.5 × 5 mm，含 0°/90° 两种朝向）在当前板材有效幅面 8 × 90 mm 与已排 1 个标签之后已无空位可放……`

## 压印路径模式

在**排版模式**或**多标签拼版**页签完成一次成功结果后，左侧表单底部的「**压印路径**」区域即可使用：填写**起点 X / Y（mm，压印机机头的起始位置，可以在板材外）**，点击「**生成压印路径**」。修改起点（在已有结果时）会自动防抖重算；排版/拼版参数一旦变化，旧路径立即作废，需重新生成（避免路径与凸点错位）。

算法与输出：

1. **最近邻初始路线**：从用户起点出发，每一步走到距当前位置最近的未访问凸点；距离相同时依次按 **① 标签索引升序（拼版点；单标签点同组）→ ② 点坐标 x 升序、再 y 升序 → ③ 原序号（输入 `dots` 数组下标）升序**决胜，故相同输入结果严格一致；
2. **2-opt 局部优化**：最多执行 **20 轮**，每轮按反转段起点下标 `i` 升序、终点下标 `j` 升序扫描，接受**首个使空移总长严格缩短**的反转并立即结束本轮（下一轮重新从头扫描）；某轮无严格缩短反转时提前结束。反转段允许包含首点（更换起点连接的第一个凸点）与末点；
3. 结果是凸点下标的一个**排列**，**每个凸点恰好压印一次**；步骤间空移距离逐段给出（第 1 步为“用户起点 → 首点”）。

界面与下载：

- 统计条显示**优化前空移总长（最近邻）→ 优化后空移总长、节省 mm 与节省比例（%）**及实际执行的 2-opt 轮数（`n/20`）；
- 右侧「**压印路径预览**」叠加在板材坐标系上：绿色三角为用户起点，灰色虚线为最近邻初始路线，蓝色实线 + 箭头为优化后作业方向，每个凸点旁标注 **step 序号**（首点绿圈、末点橙圈；拼版点保留 `data-label`）；
- 「**下载压印 CSV**」为 UTF-8 BOM（Excel 可直接打开）、CRLF 行尾，表头固定为 **`step,label,x_mm,y_mm,travel_mm`**：`step` 从 1 连续编号，`label` 为拼版点所属标签索引（单标签路径留空），`x_mm/y_mm` 为凸点毫米坐标，`travel_mm` 为上一位置到该点的空移距离（第 1 行 = 起点到首点）。

约束与报错：单次路径凸点数**上限 2000**（超过即报 `超过单次压印路径 2000 个上限`）；起点必须为数字、凸点坐标必须合法（逐个定位到第几个点）；任一条件不满足时 `ok=false`，`steps/svg/csv` 全部为空——**绝不输出部分路径**。

## 拼版裁切线模式

在「**多标签拼版**」页签完成一次**成功拼版**后，左侧表单底部的「**拼版裁切线**」区域即可使用（拼版失败或参数变化时旧裁切线立即作废，避免刀路与凸点错位）。输入两个参数：

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| 最小留边 (mm) | 凸点（含凸点半径的包络）到**矩形成品边**的最小距离，非负 | 0.5 |
| 刀具半径 (mm) | 切割刀具半径，成品边再外扩该值得到**刀心线**（刀具中心轨迹），非负 | 0.5 |

点击「**生成裁切线**」（修改参数且已有结果时自动防抖重算）；「**取最大留边**」一键把留边设为整版允许的最大值并重算。

三层矩形（每条标签都在**板材全局坐标系**中直接计算——90° 旋转标签使用的是旋转后的全局凸点，不做反向旋转）：

1. **凸点包络 envelope**：该标签全部 `(凸点中心 x/y, 凸点半径 r)` 的轴对齐包围盒，即四边取 `min(x−r) / max(x+r) / min(y−r) / max(y+r)`；
2. **成品边 finish_edge**：包络四边整体**外扩最小留边** `m`；
3. **刀心线 tool_center**：成品边四边再整体**外扩刀具半径** `R`（等价于包络外扩 `m + R`），矩形四角即下刀中心的毫米坐标。

**整版最大统一留边 `maxMargin`** 取以下全部约束的最小值：

- **板材边缘**（每条标签 4 条）：刀心线必须落在板材内——
  左/上 `m ≤ env.x0 − R`、`m ≤ env.y0 − R`，右/下 `m ≤ W − env.x1 − R`、`m ≤ H − env.y1 − R`；
- **标签对刀具占位**（每对标签一条）：设两个凸点包络在 x、y 轴上的净间距为 `gx、gy`（投影重叠时净间距为 0），取较大轴为**分离轴**，则
  **`m ≤ max(gx, gy) / 2 − R`**——两条刀心线在分离轴上的间距为 `g_axis − 2R − 2m`，必须 ≥ 0（另一轴两标签本就不重叠，刀具互不占位）。

约束按“限值最小 → 板边优先于标签对 → 方向（左/上/右/下）→ 标签索引、标签对索引”稳定排序，故最紧约束 `binding` 与最大留边对相同输入严格一致；即使刀具半径大到 `maxMargin` 为负（任何留边都放不下）也会明确给出该负值与最紧约束。

- **输入留边可行**（`m ≤ maxMargin`，贴线恰好可行）：右侧「**裁切线叠加预览**」在板材坐标系上叠加黄色虚线凸点包络、黑色全局凸点、蓝/橙（0°/90°）成品边、红色刀心线，并在每个刀心线四角标注 `TL/TR/BR/BL x,y`（mm）与标签编号；统计条显示最大统一留边、最紧约束来源（某标签的某条板边，或某标签对的水平/竖直分离轴）、贴线约束数与当前余量；
- **输入留边超限**：`ok=false`，`labels/svg/csv` 全空——**不输出部分刀路**；`errors[]` 列出**所有**被违反的板边（`plate-edge-limit`，含标签号与方向）与标签对（`label-pair-limit`，含两个标签号、分离轴与两轴净间距），首条 `binding:true` 为最紧约束并给出 `maxMargin`，末条汇总其余违反处数量与“降至 maxMargin 即可行”的提示。

**下载裁切线 CSV**（UTF-8 BOM、CRLF，Excel 可直接打开）：每条标签两行（`finish_edge` / `tool_center`），表头固定为

```
label_index,rotation_deg,rect,corner_tl_x_mm,corner_tl_y_mm,corner_tr_x_mm,corner_tr_y_mm,corner_br_x_mm,corner_br_y_mm,corner_bl_x_mm,corner_bl_y_mm
```

四角顺序为 TL（左上）→ TR（右上）→ BR（右下）→ BL（左下），原点在板材左上角、y 向下。**下载裁切线 SVG** 为自包含整板叠加文档（`width/height` 以 mm 标注，含全局凸点、三层矩形、标签编号与四角坐标文本）。

## 压印质检模式

进入「压印质检」页签后，先用左侧两个基准按钮选择基准来源：

- **单标签排版基准**：最近一次成功的单标签排版（左侧绿色基准条显示基准标签文字、设计点数与排版时间；排版失败不会覆盖基准）；
- **最近拼版基准**：最近一次成功的多标签拼版，**一键选用**即可——基准条显示标签数量、旋转 90° 条数、设计点总数，并逐个列出标签的**索引 / 旋转角**（`#n` / `#n ⟳90°`，悬停显示原文）；质检请求直接发送拼版返回的顶层 `dots`（每个点保留 `label`、`rotation` 元数据）。**尚无成功拼版时该按钮禁用**（悬浮提示先完成拼版），基准条黄色提示先去拼版；拼版失败不会覆盖已有拼版基准。

切换基准会清空上一次质检结果并（在已粘贴 CSV 时）自动按新基准重跑；切回单标签排版时仍可继续使用单标签基准，原有 API 参数与调用方式完全兼容。

| 输入 | 含义 |
| --- | --- |
| 实测凸点 CSV | 每行一个点，两列 `x_mm,y_mm`（mm）；首行可为 `x_mm,y_mm` 表头（可省略），允许空行；**点的顺序无须与设计点对应** |
| X / Y 校准偏移 | 对旋转后的实测坐标再整体平移：比较坐标 = R(旋转角)·(实测−板材中心) + 板材中心 + (offsetX, offsetY) |
| 校准旋转角 | 实测点围绕板材中心（板材幅面之半）的刚体旋转角（度，逆时针为正），默认 0；由「一键自动校准」自动写回 |
| 合格公差 | 配对欧氏距离 ≤ 公差判为「合格」，否则为「偏移超差」 |
| 最大关联半径 | 只有设计点与刚体校准后实测点距离 ≤ 半径时才允许配对 |
| X / Y 最大校准量 | 「一键自动校准」的候选限幅：仅保留 \|dx\|、\|dy\| 均不超限的候选平移（默认 2 mm） |
| 最大旋转角 / 角度步长 | 小角度刚体搜索范围与采样步长（度）：角度在 `[-最大旋转角, 最大旋转角]` 内按步长枚举（含 0°）。最大旋转角留 `0` 时只估平移（与旧版一致）；最大旋转角上限 15° |

比较算法：在关联半径构成的二分图上做**一对一最优匹配**，优先级依次为 ① 匹配对数最多 → ② 总欧氏距离最小 → ③ 再相同则按设计点序号与 CSV 行号稳定决胜（每个实测点最多匹配一个设计点，绝不重复配对）。未配对的设计点记为**缺失**，未配对的实测点记为**多余**。

### 一键自动校准（全局平移 / 小角度刚体）

粘贴无序实测点、设好 **X/Y 最大校准量**后点击「**一键自动校准（平移 / 小角度刚体）**」。

**模式一：仅估算全局平移**（最大旋转角留 `0`，或直接不传角度参数，与旧版完全兼容）：

1. 以每个「设计点 i − 实测点 j」的差值 `(dx,dy)=(x设计−x实测, y设计−y实测)` 作为候选全局平移（令比较坐标 实测+(dx,dy) 尽量贴合设计）；
2. **仅保留两轴均未超限者**：`|dx| ≤ 最大X校准量` 且 `|dy| ≤ 最大Y校准量`，候选按 1e-6 mm 量化去重；
3. 每个候选都复用质检的同一套**一对一匹配**（受同一最大关联半径约束），依次按
   **① 匹配对数最多 → ② 配对总残差（欧氏距离之和）最小 → ③ |dx|+|dy| 最小 → ④ dx 升序、再 dy 升序**
   确定唯一平移。

**模式二：小角度刚体校准**（最大旋转角填正数，如 `3`，并设置角度步长，如 `0.1`）：

1. 角度在 `[-最大旋转角, 最大旋转角]` 内按步长枚举（**始终包含 0° 与两侧端点**，按 1e-6 度去重），最大旋转角不得超过 15°、枚举角度数不超过 201 个；
2. 每个候选角度先把**实测点围绕板材中心**（`plateWidth/2, plateHeight/2`；未提供板材幅面时取设计点包围盒中心）做刚体旋转，再在现有 **X/Y 限幅内枚举候选平移**，即「角度 × 平移」联合搜索，候选评估总数有上限保护（20 万个）；
3. 每个（角度, 平移）候选都复用质检的同一套**一对一匹配**，依次按
   **① 匹配对数最多 → ② 配对总残差最小 → ③ 旋转角绝对值最小（能不转就不转）→ ④ |dx|+|dy| 最小 → ⑤ dx 升序、dy 升序、角度升序**
   确定唯一刚体参数；
4. 估算的**旋转角写回「校准旋转角」、平移写回 X/Y 偏移输入框并立即重跑**合格/偏移超差/缺失/多余四类判定，绿色提示条同步显示角度个数、角度×平移候选数、匹配对数、总残差与旋转中心。

注意：两种模式下缺失的设计点和多余的实测点都不参与任何候选的配对统计，因此**不会被离群点拉偏——本功能不使用质心差替代**。若搜索范围内没有任何有效候选（或参数/CSV 非法、计算量超上限），**角度与偏移输入框全部保留原值不变**，并在黄色提示条中给出明确原因（是角度范围不足、平移限幅过小还是 CSV/半径问题），不会清空或写入错误参数。

- CSV 解析错误会逐条定位到**具体物理行号（和列号）**，例如 `第 3 行：列数为 1，应为 2 列（x_mm,y_mm）`
- 叠加 SVG 用四类颜色区分：🟩 合格（绿）/ 🟧 偏移超差（橙）/ 🟥 缺失（红）/ 🟣 多余（紫）；○ 为设计点、◆ 为经刚体校准（旋转+平移）后的实测点，细线连接配对；元素上带 `data-rotation`、`data-center-x/y`、`data-measured-x/y` 属性，图内 `<desc>` 注明所用角度与中心。**拼版基准**下另以淡色虚线框画出**每个标签的边界并标注 `#n` / `⟳90°`**（0° 蓝、90° 橙），配对与缺失元素带 `data-label`、`data-label-rotation`，连线/圆/菱形均可对应到标签
- 指标：**通过率**（合格对数 / 设计点总数）、**最大偏差**、**平均偏差**（均只统计配对点），以及配对/缺失/多余计数；拼版基准下统计条还显示标签数
- **下载质检报告 CSV**：含设计点序号、**所属标签 `label_index` 与标签旋转角 `label_rotation_deg`**（单标签基准留空）、设计坐标、CSV 行号与**原始实测坐标**、**校正（旋转+平移后）坐标**、配对距离、中文结论（合格/偏移超差/缺失/多余）与**该行所用旋转角 `rotation_deg`**，并附汇总行（含 `label_count`）及参数行（含旋转角与旋转中心，UTF-8 BOM，Excel 可直接打开）；另可下载叠加 SVG

## API

### `POST /api/decode`

点阵解码：请求体只需一个字符串字段 `text`（六点盲文 Unicode，≤5000 字符）：

```json
{ "text": "⠠⠑⠠⠭⠠⠊⠠⠞⠀⠠⠙⠕⠕⠗⠀⠼⠉⠲⠁⠙" }
```

返回 `{ ok, decodedText, cells, errors }`：

```json
{
  "ok": true,
  "decodedText": "EXIT Door 3.14",
  "cells": [
    { "index": 0, "position": 0, "char": "", "braille": "⠠", "dots": [6], "kind": "caps-prefix", "uppercase": false, "error": false },
    { "index": 1, "position": 1, "char": "E", "braille": "⠑", "dots": [1,5], "kind": "letter", "uppercase": true, "error": false }
  ],
  "errors": []
}
```

- `decodedText`：还原文本（英文、大写、连续数字段），空白与标点原样保留；**未知字符也原样保留，绝不静默丢弃**；
- `cells[]`：逐单元对照，每项含 `index`（0 基单元序号）、`position`（在输入字符串中的 UTF-16 偏移，可直接用于前端选区定位）、`char`（该单元还原出的字符；前缀单元为空串）、`braille`（盲文原字；普通空白为空串）、`dots`（点号 1–6 数组）、`kind`（`letter | digit | punct | caps-prefix | number-prefix | space | unknown`）、`uppercase`（字母是否由大写前缀作用）、`error`（该单元是否对应一条错误）；
- `ok=true` 仅当没有任何未知/悬空单元；`ok=false` 时 `errors[]` **逐个未知字符**给出：
  ```json
  { "type": "unknown-pattern", "index": 2, "position": 2, "char": "⠿", "codePoint": "U+283F", "dots": [1,2,3,4,5,6], "length": 1,
    "message": "第 3 个字符（位置 2）“⠿”（U+283F）是盲文图案但点位为点 1、2、3、4、5、6，现有字符表（A–Z、0–9 及常用标点）未收录该点位，已原样保留在结果中，未静默丢弃。" }
  ```
  错误类型：`unknown-char`（非盲文字符，含 `codePoint`）、`unknown-pattern`（码表未收录的盲文点位，另含 `dots`）、`dangling-caps-prefix`（悬空的 `⠠`）、`bad-input`（`text` 非字符串）、`input-too-long`（超 5000 字符）；非 BMP 字符按完整码点报告，`length` 为其 UTF-16 长度。

### `POST /api/layout`

```json
{ "text": "EXIT Door 2", "plateWidth": 100, "plateHeight": 50, "dotSpacing": 2.5, "lineSpacing": 10, "margin": 5 }
```

返回 `{ ok, errors, params, cellsPerLine, maxLines, lines, dots, brailleText, stats, svg }`：

- `ok=false` 时 `errors` 列出放不下的具体原因，`svg/dots` 为空（不输出裁切结果）
- `dots[].x/y/r` 为每个凸点的毫米坐标，`svg` 为完整 SVG 文档（`width/height` 以 mm 标注）

### `POST /api/panel`

多标签拼版。`labels` 为字符串（每行一条）或字符串数组；其余为所有标签共享的板材/点距/行距/边距/标签间距参数：

```json
{
  "labels": "EXIT\nWOMEN\nMEN",
  "plateWidth": 120, "plateHeight": 80,
  "dotSpacing": 2.5, "lineSpacing": 10,
  "margin": 5, "labelGap": 5
}
```

返回 `{ ok, errors, mode:"panel", params, labelCount, skippedBlank, labels[], dots[], stats, svg }`：

- `ok=true` 时：
  - `labels[]` 逐条为 `{ index, sourceLine, text, brailleText, cells, rotation(0|90), x, y, localWidth, localHeight, placedWidth, placedHeight, bounds:{x,y,width,height}, dots[] }`；`x/y` 为标签局部原点锚点（90° 时在包围盒右上角），`bounds` 为板材上的包围矩形；
  - 顶层 `dots[]` 是所有标签凸点的展平数组，元素为单标签点结构 `{x,y,r,line,cell,dot}` 加上 `{label, rotation, localX, localY}`，可直接传给 `/api/qc`；
  - `stats` 含 `labelCount / skippedBlank / rotatedCount / totalCells / totalDots / packWidth / packHeight / labelArea / remainingArea / usableWidth / usableHeight`；
  - `svg` 为整板 SVG：每个标签一个 `<g data-label-index data-rotation>`，内含边界矩形、`<title>`（索引+原文+角度）与 `translate(...) [rotate(90)]` 后的凸点。
- `ok=false` 时 `labels/dots` 为空数组、`svg=null`，`errors[]` **逐条**列出问题标签（带 `labelIndex`；类型为 `label-unsupported-char / label-too-long / label-too-wide / label-pack-fail` 或参数错误），不输出任何部分版面。

### `POST /api/path`

压印路径。`dots` 取最近一次成功的 `/api/layout`（单标签点 `{x,y,r,...}`）或 `/api/panel`（拼版顶层 `dots[]`，额外含 `label` 等元数据）的返回结果；起点为压印机机头初始位置（mm，允许在板材外）：

```json
{
  "dots": [{ "x": 5, "y": 5, "r": 0.75 }, { "x": 7.5, "y": 5, "r": 0.75 }],
  "startX": 0, "startY": 0,
  "plateWidth": 100, "plateHeight": 50
}
```

- 流程：最近邻（同距离按标签索引 → x → y → 原序号稳定决胜）→ 最多 20 轮 2-opt（每轮按 i、j 下标顺序接受首个**严格缩短**的反转）；
- 返回 `{ ok, errors, params:{startX,startY,maxRounds,pointLimit}, pointCount, steps[], stats, svg, csv }`；
- `steps[]` 每个凸点恰好一项：`{ step, label, seq, x, y, travel_mm }`，`step` 1 基连续、`seq` 为输入 dots 的 1 基原序号，`label` 单标签为 `null` / 拼版为标签索引，`travel_mm` 为上一步到该点的空移（首步 = 起点到首点）；
- `stats` 含 `pointCount / labelCount / nnTravelMm / optTravelMm / savedMm / savedPercent / roundsRun / maxRounds`；
- `svg` 为叠加预览（灰虚线最近邻路线、蓝实线带 `marker-mid/marker-end` 方向箭头、绿三角起点、每点 `class="path-stop" data-step data-seq [data-label]` 与 step 序号，首点绿圈末点橙圈）；
- `csv` 为带 UTF-8 BOM 的下载文本，表头 **`step,label,x_mm,y_mm,travel_mm`**。
- `ok=false`（点数超过 2000、`dots` 缺失/为空、起点非数字、点坐标非法、板材尺寸非法）时 `steps` 为空数组、`stats/svg/csv` 为 `null`，`errors[]` 明确给出原因（点数错误类型 `too-many-points`），不输出任何部分路径。

### `POST /api/panel/cut`

拼版裁切线。复用一次成功 `/api/panel` 的结果：`labels` 直接取响应的 `labels[]`（每项需含 `index` 与全局 `dots[]{x,y,r}`）；也可只传顶层 `dots[]`（点必须带 1 基 `label` 字段），接口按标签编号自动分组。`plateWidth/plateHeight` 取拼版板材尺寸：

```json
{
  "labels": [ { "index": 1, "rotation": 0, "dots": [{ "x": 7.5, "y": 5, "r": 0.75 }] } ],
  "plateWidth": 120, "plateHeight": 80,
  "minMargin": 0.5, "toolRadius": 0.5
}
```

返回 `{ ok, errors, params, labelCount, maxMargin, binding, labels[], stats, svg, csv }`：

- 三层矩形按全局坐标计算：`labels[].envelope`（凸点中心+凸点半径包络）、`finish`（外扩 `minMargin` 的成品边）、`toolCenter`（再外扩 `toolRadius` 的刀心线），均为 `{x,y,width,height}`；`corners[]` 按 `TL/TR/BR/BL` 给出刀心线四角 `{corner,x,y}` 毫米坐标；另含 `index/text/rotation/dotCount`；
- `maxMargin` 为**整版允许的最大统一留边**（板边 + 标签对刀具占位两类约束的最小值）；`binding` 描述最紧约束：板边时 `{kind:"plate",side:"left|right|top|bottom",label,limit}`，标签对时 `{kind:"pair",labelA,labelB,axis:"x|y",gapX,gapY,limit}`；
- `stats` 含 `labelCount/minMargin/toolRadius/maxMargin/slack(=maxMargin−minMargin)/plateConstraints/pairConstraints/bindingCount`；
- `csv` 表头 **`label_index,rotation_deg,rect,corner_tl_x_mm,...,corner_bl_y_mm`**，每标签 `finish_edge` / `tool_center` 两行（UTF-8 BOM、CRLF）；`svg` 为自包含整板叠加图（`cut-envelope` 黄虚线、`cut-dots` 全局凸点、`cut-finish` 成品边、`cut-tool-center` 红刀心线、`cut-label-index` 编号、`cut-corner` 四角坐标，每组带 `data-label-index/data-rotation`）；
- `ok=false`（留边超限、刀具半径过大使 `maxMargin<0`、缺拼版数据、留边/刀具半径为负、板材尺寸非法、凸点坐标非法）时 `labels` 为空、`svg/csv=null`，**不输出任何部分刀路**；超限时 `errors[]` 首条 `binding:true` 指出最紧的板边（类型 `plate-edge-limit`）或标签对（类型 `label-pair-limit`，含 `labelA/labelB/axis/gapX/gapY/limit`），其后列出全部其余违反项，末条类型 `limit-summary`；参数错误类型为 `param`，无拼版数据为 `no-panel`。

### `POST /api/qc`

```json
{
  "design": [{ "x": 5, "y": 5, "r": 0.75 }],
  "csv": "x_mm,y_mm\n5.2,4.9",
  "offsetX": 0, "offsetY": 0, "rotation": 0,
  "tolerance": 0.5, "maxRadius": 2,
  "plateWidth": 100, "plateHeight": 50
}
```

返回 `{ ok, errors, params, baseline, transform, measuredCount, pairs, missing, extra, stats, svg, csv }`：

- `ok=false` 时 `errors[]` 含参数错误与逐行（`line` 列）CSV 解析错误，`svg/csv` 为空
- `params.rotation` 为本次质检使用的旋转角（度，缺省请求字段时为 `0`）；`transform.centerX/centerY` 为旋转中心（板材中心，缺幅面时为设计点包围盒中心）
- `pairs[]` 含双方坐标、**原始实测坐标** `measuredX/Y`、**校正坐标** `correctedX/Y`、距离与 `verdict`（`pass` / `offset`）；`missing[]`、`extra[]` 为未配项
- `baseline` 含 `count` 与板材幅面；传入拼版顶层 `dots` 时另含 **`labelCount` 与 `labels[]{index,rotation,dotCount}`**（各标签索引/旋转角），`pairs[]` 与 `missing[]` 的每项带 **`label`（标签 1 基索引）与 `labelRotation`（标签拼版旋转角 0/90）**；单标签基准下 `labelCount=0`、这两个字段为 `null`
- `stats` 含 `passRatePercent`、`maxDeviation`、`meanDeviation` 等；叠加 SVG 在拼版基准下额外绘制标签边界（`data-label-count`、`class="qc-label" data-label-index data-rotation`、点元素 `data-label/data-label-rotation`）；`csv` 为可直接下载的报告文本（明细含 `label_index,label_rotation_deg`，末列 `rotation_deg` 为质检校准角，参数行含旋转角与旋转中心）。请求参数与旧版完全一致——拼版点只是带有额外字段的 `{x,y,r,...}` 超集

### `POST /api/qc/calibrate`

纯平移（旧调用，不传任何角度字段，完全向后兼容）：

```json
{
  "design": [{ "x": 5, "y": 5, "r": 0.75 }],
  "csv": "5.4,5.25",
  "maxOffsetX": 2, "maxOffsetY": 2,
  "maxRadius": 2
}
```

小角度刚体校准（新增 `maxAngle` / `angleStep`，均为度；另建议传板材幅面以确定旋转中心）：

```json
{
  "design": [{ "x": 20, "y": 15 }],
  "csv": "20.1,14.8",
  "maxOffsetX": 2, "maxOffsetY": 2,
  "maxRadius": 2,
  "maxAngle": 3, "angleStep": 0.1,
  "plateWidth": 100, "plateHeight": 50
}
```

自动校准：纯平移模式枚举「设计点－实测点」候选平移并限幅去重；刚体模式在 `±maxAngle` 内按步长枚举角度（含 0°），实测点围绕板材中心旋转后再枚举限幅内平移。每个候选复用一对一匹配，按匹配数 → 总残差 →（刚体模式）旋转绝对值 → |dx|+|dy| → dx/dy/角度升序决出唯一结果。

返回 `{ ok, errors, offsetX, offsetY, rotation, centerX, centerY, matchedCount, totalResidual, designCount, measuredCount, candidateCount, rigidMode, angleCount }`：

- `ok=true` 时 `offsetX/offsetY` 为建议写回偏移框的平移（mm，4 位小数），`rotation` 为旋转角（纯平移模式恒为 `0`），`centerX/centerY` 为旋转中心；`matchedCount` 为该参数下的匹配对数，`totalResidual` 为配对总残差，`candidateCount` 为限幅去重后的候选数（刚体模式为各角度候选总数），`rigidMode` 标识是否启用了角度搜索，`angleCount` 为枚举角度数（纯平移模式为 `null`）；
- `ok=false`（无可用候选、参数/CSV 错误、点数或计算量超上限）时 `offsetX/offsetY/rotation` 均为 `null`，`errors[]` 给出明确原因，调用方应保留角度与偏移输入框原值。只传 `maxAngle` 与 `angleStep` 其中之一会被视为参数错误（不会静默退化为纯平移）。

健康检查：`GET /api/health`

## 项目结构

```
├── server.js            # Express 服务：静态页面 + /api/decode + /api/layout + /api/panel + /api/panel/cut + /api/path + /api/qc + /api/qc/calibrate
├── lib/braille.js       # 核心：一级盲文转换、点阵解码（盲文 -> 文本/逐单元/未知字符定位）、整词换行排版、毫米坐标 SVG 生成
├── lib/panel.js         # 核心：多标签解析、单行矩形复用、0/90° 行级装箱（剩余面积最小稳定择优）、整板 SVG/JSON
├── lib/cut.js           # 核心：拼版裁切线（凸点包络 -> 外扩留边成品边 -> 外扩刀具半径刀心线、板边/标签对最大统一留边约束、四角 CSV/叠加 SVG）
├── lib/path.js          # 核心：压印路径（最近邻 + 同距离稳定决胜、最多 20 轮首改进 2-opt、steps/CSV/叠加 SVG）
├── lib/qc.js            # 核心：实测 CSV 解析（行号定位）、一对一最优匹配、判定/SVG/CSV 报告、自动校准（纯平移 + 小角度刚体）
├── public/              # 原生前端（index.html / app.js / style.css，四个页签：点阵解码 + 排版/拼版（内置压印路径与拼版裁切线区）+ 质检）
├── test/                # node:test 单元/接口测试（点阵解码 + 排版 + 拼版 + 裁切线 + 压印路径 + 质检 + HTTP API）
├── Dockerfile           # 单阶段构建，npm install + 启动
└── docker-compose.yml   # 一条命令编排启动
```
